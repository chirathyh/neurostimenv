Recovery design
Use the additive recovery entry point; do not rerun complete-pilot for this case.
It verifies upstream receipts, source/config/runtime identity and original file
hashes. Native simulator imports and invocation entry points are blocked. It does
not call generation, state recovery or complete-state fitting. The original
ledger, generation provenance and completed state-model evidence remain unchanged.
Each unfinished TCN runs once in a fresh Python subprocess, with the same CUDA
configuration and a separate fault-handler log. Failure stops rather than retrying
or silently switching to CPU. This isolation is a recovery measure; success on the
workstation is not claimed from CPU tests.

The completion-record fix changes the learning module's hash. Existing ridge
readouts are reused only through a narrowly validated compatibility adapter: the
current source must equal the exact approved patch of the hash-checked original
commit. It verifies the original input/settings signature and all saved output
hashes. Old results are not relabeled as newly fitted or overwritten. New fits use
the current implementation signature. The compatibility record is saved separately.

Reproduced implementation defect
Waveforms and Fourier coefficients are extracted one native trial at a time.
Frozen T4 energy/log-energy targets are then derived in a three-dimensional
(context, future, Fourier coordinate) array. The old replay check instead applied
the band-energy sum to a single one-dimensional coefficient vector. NumPy's
advanced-indexing layout changes the reduction order, so identical coefficients
can produce an energy differing by a few float64 ULPs.

Using the verified original source archive's A0 T3 lead10 evaluation coefficients,
the registered s36012-p0000-R0-score-0001 low-beta energy differs by exactly one
ULP (3.76158192263132e-37 V^2) between these two calculations. High-beta energy
also differs by one ULP for both registered replay observations. Applying the
original multi-record arithmetic reproduces all three bands and their logarithms
exactly for both observations. This is a local reproduction using saved Fourier
coefficients, not a new examination of the latest workstation native recordings.
The old error omitted the failing job; the workstation must pass its exact checks
before this recovery can be declared complete.

Correction and boundaries
precision.py now extracts native T3 coefficients per trial, then computes replay
T4 energy/log energy with the same multi-record reduction as frozen derivation.
It requires at least two records; the pilot has exactly two registered replay
contexts. No scientific replicate is fabricated. Native T0/T3 transforms, all
frozen arrays, normalization, learning.py, model signatures and simulator code are
unchanged. Exact array equality remains mandatory. No np.allclose tolerance was
introduced. A true mismatch now records the job/context/future, exact physical
arrays, support and difference in precision/replay_target_failures/. Each verified
job writes precision/replay/<job>/target_consistency.json, included in the export.

Report-stage cancellation and receipt correction, 18 November 2026

ordinary fitting/scoring and H2/replay scoring returned. This error comes from
report input validation. The original detailed failing row was not printed.

The reporting defect is reproducible even for a training-mean predictor whose
risk exactly equals its reference. For risk=reference=1.234567891234e-18,
100*risk/reference rounds to100.00000000000001. The scoring calculation
100*(1-risk/reference) is exactly0, but the report's alternative100-error is
-1.4210854715202004e-14 percentage points. A relative tolerance scaled only to
these near-zero results falsely rejects mathematically consistent metrics.

The report now checks this display identity using the existing comparison plus
a float64 roundoff allowance of8*epsilon*(100+abs(error_baseline100)). Near the
baseline this is about3.55e-13 percentage points. This allowance applies only to
the percentage-point display identity. Physical-risk/denominator checks and exact
native/frozen-target equality remain unchanged. Verified supplied risks, display
errors and gains retain their original unrounded values, including zero and tiny
negative gains. Incorrect signs, percentage/fraction conventions and altered
physical denominators still fail. Any mismatch now identifies table/row/job,
method and both numerical values.
